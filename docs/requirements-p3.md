# Phase 3 要件 — AIによる対応方針コメント（`--ai`）

> 2026-08-29 にオーナー裁定を反映して確定。
> 裁定の内容は末尾の「決定事項」にまとめてある。

## ゴール
Phase 1 / Phase 2 で作ったトリアージレポートの各CVEに、
**「で、どうすればいいのか」を1〜2行で書いた対応方針コメント**を付けられるようにする。

```
triage-lens report trivy-result.json --ai -o triage-report.md
```

優先順位（P0〜P3）は「どれから手を付けるか」までしか教えてくれない。
その次に必ず出てくる「これは何をすればいいのか」を、
Claude API に短く書かせてレポートに載せる。

**既定の動作（`--ai` を付けない場合）は Phase 2 から一切変えない。**
`--ai` を付けなければ、Anthropic への通信は1回も発生しない。

## スコープ
1. `--ai` オプションの追加（既定は無効）
2. Claude API で各CVEに1〜2行の対応方針コメントを生成し、レポートに含める
3. APIキーは環境変数から読む。未設定なら生成をスキップする
4. 生成に失敗してもレポート本体は壊さない
5. README 更新（日英）

上記以外は実装しない。

## 機能要件

### 1. CLI

追加するオプション:

| オプション | 既定値 | 内容 |
| --- | --- | --- |
| `--ai` | 無効 | AIによる対応方針コメントを生成する |
| `--ai-limit N` | 50 | 生成対象の上限件数 |
| `--ai-model NAME` | `claude-haiku-4-5` | 使用するモデル |

- `--ai` を付けたときだけ、Anthropic への通信が発生する
- 既存のオプション（`--top` / `-o` / `--lang`）との組み合わせで挙動が変わらないこと
- 終了コードは Phase 1 の定義を変えない。
  **AI コメントの生成失敗を理由に終了コードを変えない**（0 のまま）
- **費用が発生する前の確認プロンプトは出さない**（CI やスクリプトから使えなくなるため）。
  代わりに `--ai-limit` の既定値で上限を設け、実行前に標準エラーへ1行
  「N件に対してAIコメントを生成します（モデル: ...）」と出す

### 2. APIキーの扱い

- APIキーは環境変数 `ANTHROPIC_API_KEY` から読む
- **キーをコマンドライン引数で受け取らない**。`--api-key` のようなオプションは作らない
  （シェル履歴・`ps` の出力・CI のログにキーが残るため）
- **設定ファイルにキーを書かせない**
- 環境変数が未設定、または空文字の場合:
  - AI コメントの生成を**行わない**（通信は1回も発生しない）
  - **エラーにしない**。終了コードは 0
  - レポートは Phase 2 と同じ内容で出力される（AI の欄が増えない）
  - **標準エラーに1行だけ**
    「ANTHROPIC_API_KEY が未設定のためAIコメントをスキップしました」と出す。
    黙って機能が消えるのは「静かに壊れる」状態なので、明示する。
    ただし**レポート本文には書かない**（レポートは成果物であり、実行環境の話は書かない）
- キーが無効（401 / 403）だった場合も、後述の「生成失敗」と同じ扱いにする。
  キーの中身をエラーメッセージやレポートに出さない

### 3. 生成する内容

各CVEについて、**1〜2行（日本語で最大120文字程度）**の対応方針を書かせる。

書かせたいこと:
- まず何をするのが妥当か（例: 修正版に上げる / 修正版が無いので緩和策を採る / 影響範囲を確認する）
- そのCVEに固有の注意点があれば一言

書かせないこと（プロンプトで明示的に禁止する）:
- **優先度の判定**。P0〜P3 は triage-lens が公開データから決める。AIに上書きさせない
- 「危険です」「至急対応してください」のような、判断材料を増やさない煽り
- CVE の詳細な技術解説（レポートが長くなるだけ）
- 実在しないバージョン番号やコマンドの提示（後述の免責と合わせて扱う）

### 4. 外部に送信するデータ

triage-lens は脆弱性スキャン結果を扱うツールであり、入力には利用者の内部情報が含まれうる。
**送るものを最小限に固定し、要件として明記する。**
この表は CLAUDE.md 絶対ルール4の例外条項から参照されている。**変更にはオーナーの承認が要る。**

| 項目 | 送る | 理由 |
| --- | --- | --- |
| CVE ID | ○ | 公開情報。生成の主材料 |
| パッケージ名 | ○ | 公開情報。対応方針がパッケージに依存するため |
| 現バージョン / 修正バージョン | ○ | 「上げれば済むのか」を判断させるため |
| CVSS / EPSS / KEV掲載有無 | ○ | 公開情報。緩急の表現に使うため |
| 優先度ランク（P0〜P3） | ○ | 文面のトーンを合わせるため（判定はさせない） |
| **検出箇所（パス / purl）** | **×** | 利用者の内部構成が推測できるため送らない |
| **対象名（プロジェクト名 / イメージ名）** | **×** | 同上 |
| 入力ファイルそのもの | × | 送る必要がない |

- 送信内容は**1箇所の関数にまとめ**、「何を送っているか」がテストで固定できる形にする
- README に「`--ai` を付けたとき、何が Anthropic に送られるか」の表を載せる

### 5. レポートへの出し方

- 一覧表に列を増やさない（横に伸びて読めなくなるため）。
  **各ランクの節の中、一覧表の下に「対応方針」の小見出しを作り、1件1〜2行で並べる**
- AI コメントが取れなかったCVEは、**その行に何も足さない**（「生成失敗」と書かない。
  行が失敗の告知で埋まるとレポートが読めなくなる）
- レポートの末尾に、AIコメントを1件でも含む場合のみ次を書く:
  - 免責:「対応方針コメントは AI が生成した参考情報です。実行前に内容をご確認ください。」
  - **使用したモデル名**（後から「これは何が書いたのか」を追えるようにするため）
  - 対象範囲（P0 / P1 のみであること）
  - `--ai-limit` で打ち切った場合はその件数

#### 生成された文字列の扱い（重要）
AI の出力は**外部から来た文字列**として扱う。そのままMarkdownに埋めない。

- 改行・復帰・連続する空白は1つの空白に潰す（表と節の構造を壊さないため）
- `|` はエスケープする（Phase 2 の重複除去表と同じ理由）
- `<` `>` は実体参照に置き換える（HTMLタグをそのまま出さない）
- `[` `]` とバッククォートはエスケープする（リンク記法・画像記法・コード記法を無効化する）
- 長さの上限を超えた出力は切り詰める。上限は定数として1箇所に置く

### 6. 生成に失敗したときの挙動

**レポート本体は必ず出す。** これは Phase 1 の「外部APIが落ちてもCVSSだけで続行する」と同じ方針。

| 失敗の種類 | 挙動 |
| --- | --- |
| APIキー未設定 | 通信せずスキップ。標準エラーに1行。終了コード 0 |
| 認証エラー（401 / 403） | リトライしない。AI コメント無しでレポートを出す。終了コード 0 |
| 要求が不正（400 等） | リトライしない。同上 |
| レート制限（429） | `retry-after` を尊重してリトライ。諦めたらそのチャンクをスキップ |
| サーバエラー（5xx）/ タイムアウト / 通信断 | 指数バックオフでリトライ。諦めたらそのチャンクをスキップ |
| 応答が想定した形式でない | そのチャンクだけスキップ。**例外を投げない** |
| 一部のCVEだけ生成できた | **取れたぶんだけ載せる**。全部捨てない |
| 1件も生成できなかった | レポートは `--ai` 無しと同一。標準エラーに1行出す |

- 利用者にスタックトレースを見せない（Phase 1 / Phase 2 と同じ）
- AI 部分の失敗が、EPSS / KEV の取得結果やスコアリングに影響しないこと
- 「AI を付けたのに、付けないときより壊れている」状態を作らない

### 7. コストとレート制限への配慮

コストは利用者が負担する。**黙って高額になる作りにしない。**

#### 件数を抑える
- **対象は P0 と P1 のみ。** レポートに全件表示されるのはこの2つであり、
  費用も件数に比例して抑えられる
- `--ai-limit N`（既定 50）で生成対象の上限を指定できる。上限に達したら以降は生成しない
- 上限で打ち切ったときは、レポートに「N件までを対象に生成した」と明記する
  （ROADMAP の「黙って件数を絞らない」方針に合わせる）

#### リクエストを減らす
- **1CVEにつき1リクエストを投げない。** 複数CVEを1リクエストにまとめる
  （EPSS を 100件ずつまとめているのと同じ考え方）。チャンクサイズは定数として1箇所に置く
- **送信内容が同一の検出は1回だけ問い合わせる。**
  同じCVEが複数の検出箇所で見つかった場合、検出箇所は送らないので送信内容は同一になる。
  1回の結果を両方の行に使い回す
- 応答は**構造化出力**（`output_config.format` の `json_schema`）で受け取り、
  送信時に採番したIDで対応付ける。自由文を正規表現で切り出すような読み方をしない
- システムプロンプトは固定文にして先頭に置く（プロンプトキャッシュが効く形にする）。
  ただし**キャッシュが効くことを前提にコストを見積もらない**
  （キャッシュには最小トークン数の条件があり、短いシステムプロンプトでは効かないため）

#### レート制限
- 429 応答の `retry-after` を尊重する（待ちすぎないよう上限も定数で持つ）
- リトライは指数バックオフ。回数の上限を定数で持つ
- **リトライしても意味がない応答（400 / 401 / 403 / 404）はリトライしない**
- **チャンクを並列に投げない**（直列）。
  連続して失敗したら残りのチャンクを試さず打ち切る（サーキットブレーカー）
- AI ステップ全体に**実行時間の上限**を設ける。
  ROADMAP に挙げた「外部API障害時に固まって見える」問題を、AI で再発させない

#### コストの目安（README に載せる）

前提: CVE 100件、1件あたり入力120トークン / 出力70トークン、
システムプロンプト600トークン、20件ずつ5リクエスト、キャッシュ無し。

| モデル | 入力単価 / 出力単価（100万トークン） | 1回の実行の概算 |
| --- | --- | --- |
| **Claude Haiku 4.5 (`claude-haiku-4-5`)（既定）** | $1.00 / $5.00 | 約 $0.05 |
| Claude Sonnet 5 (`claude-sonnet-5`) | $2.00 / $10.00 | 約 $0.10 |
| Claude Opus 5 (`claude-opus-5`) | $5.00 / $25.00 | 約 $0.25 |

実際には対象が P0 / P1 かつ既定で50件までなので、通常はこれより小さい。

- **モデルIDは定数として1箇所に置く。** コード中に散らさない（絶対ルール7）
- モデルごとの分岐を書かない。`--ai-model` で渡された文字列をそのまま使う

### 8. 日英対応

- `--lang ja` では日本語、`--lang en` では英語のコメントを生成する
- 免責文・モデル名の表記・対象範囲の注記は Phase 2 の `i18n` カタログに追加する
  （レポート本文に日本語リテラルを散らさない）
- 日英カタログのキー集合が一致することを検証する既存テストの対象に含める
- プロンプト本文は「レポート本文」ではないため `i18n` の対象外とし、AI モジュール側に置く

## 非機能要件

- Python 3.11+ を維持。3.11 / 3.12 / 3.13 で CI が通ること
- pytest 全緑（Phase 2 までの 393 件を含む）、ruff エラーなし
- **テストは外部に一切接続しない。** Anthropic API も含めてモック化する
- **依存パッケージを増やさない。** 公式SDK（`anthropic`）は使わず、
  既存の `httpx` で REST エンドポイントを直接呼ぶ。
  リトライ・バックオフは既存の `http_client` を拡張して再利用する
  （同じ処理を二重に書かない）
- EPSS / KEV の取得処理には手を入れない

## テスト要件

**キーとオプション**
- `--ai` を付けないと、Anthropic API へのリクエストが1回も発生しない
- `ANTHROPIC_API_KEY` 未設定で `--ai` を付けても、終了コード0でレポートが出る
- 未設定時の出力が、`--ai` を付けない場合と一致する
- 未設定時に標準エラーへ1行だけ出る
- 空文字のキーも未設定として扱う

**正常系**
- 生成されたコメントがレポートの該当ランクの節に入る
- 複数CVEが1リクエストにまとめて送られる（1件1リクエストになっていない）
- チャンクサイズを超える件数はチャンクに分かれる
- 送信内容が同一の検出は1回だけ問い合わされ、結果が両方の行に入る
- 対象が P0 / P1 に限られる（P2 / P3 は送られない）
- `--ai-limit` で件数が制限され、その旨がレポートに書かれる
- `--lang en` で英語のコメントが生成され、免責文も英語になる
- レポートに使用モデル名が出る

**送信内容**
- 送信されるデータに**検出箇所（パス / purl）と対象名が含まれない**
- 送信されるデータに CVE ID / パッケージ名 / バージョン / スコア / ランクが含まれる
- リクエストヘッダにAPIキーが入る（値がURLやクエリに出ない）

**異常系**
- 401 / 403 / 429 / 500 / タイムアウト / 通信断のいずれでも、
  レポートが出て終了コードが 0
- 401 / 403 / 400 ではリトライしない（無駄な課金と待ち時間を作らない）
- 429 の `retry-after` を尊重した待機を行う（待機処理はテストから差し替える）
- 応答が想定した形式でない場合、そのチャンクだけ落ちて他は残る
- 一部のCVEだけ生成できた場合、取れたぶんが載る
- 全件失敗した場合、レポートが `--ai` 無しの出力と一致し、標準エラーに1行出る
- 連続失敗でサーキットブレーカーが働き、残りのチャンクを試さない
- AI ステップ全体の実行時間上限で打ち切られる
- エラーメッセージ・レポートにAPIキーが含まれない

**出力の無害化**
- 生成文に含まれる `|` がエスケープされる
- 改行を含む生成文が表や節の構造を壊さない
- 長すぎる生成文が上限で切り詰められる
- HTMLタグ・リンク記法・画像記法・コード記法を含む生成文がそのまま出力されない

## Phase 2 からの非互換な変更

**無い。** `--ai` を付けない場合の出力は Phase 2 と完全に同一であること。
これを検証するテスト（同一入力での出力比較）を置く。

## Phase 3 でやらないこと（実装禁止）

- **AI に優先度（P0〜P3）を判定させること**。スコアリングは公開データによる決定的な処理のままにする
- パッチの生成、修正PRの自動作成、`package.json` 等の書き換え
- 対話モード（生成結果に対して追加で質問する等）
- 公式SDK（`anthropic` パッケージ）の導入
- Anthropic 以外のLLM / ローカルLLM への対応
- Batch API の利用（50%安いが非同期でポーリングが必要。CLIの「打ったら出る」体験と合わないため）
- 生成結果の永続キャッシュ（どこに何を保存するかの決定が別途必要になるため）
- ストリーミング表示・進捗バー
- 実行前の確認プロンプト
- CVE の詳細解説・長文の生成
- SPDX 対応、CycloneDX の XML、Web UI、設定ファイル、閾値の外部設定化（Phase 2 から継続して対象外）

## 決定事項（2026-08-29 オーナー裁定）

| 論点 | 裁定 |
| --- | --- |
| 既定モデル | **Claude Haiku 4.5**（`--ai-model` で上書き可能） |
| 依存パッケージ | **公式SDKを使わず `httpx` で直接叩く**。依存最小の規範を優先し、既存のリトライ基盤を再利用する |
| CLAUDE.md 絶対ルール4 | **改訂済み**。「例外: `--ai` 機能の Claude API のみ。キーは利用者提供、送信データは本書の表に固定」 |
| `docs/ROADMAP.md` の「AI による説明生成は対応予定なし」 | **撤回を承認**。ただし公開側の更新は **P3 リリース同期時にまとめて**行う（本Phaseでは触らない） |
| APIキー未設定時 | **折衷案を採用**。`--ai` 指定時のみ標準エラーに1行、終了コード0 |
| 対象範囲 | **P0 / P1 のみ** |
| `--ai-limit` 既定値 | **50** |
| 実行前の確認プロンプト | **出さない** |
| 免責文 | 「対応方針コメントは AI が生成した参考情報です。実行前に内容をご確認ください。」 |
| 送信データの範囲 | 要件4の表のとおり（検出箇所・対象名は送らない） |
| 公開ミラーへの反映 | P3 リリース時に判断（本Phaseの実装は dev リポジトリで完結させる） |
